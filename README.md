# Оценка качества сканов документов

Принимает скан (jpg/png/pdf) и выдаёт вердикт `good` / `acceptable` / `bad`, список
дефектов с вероятностями, локализацию (heatmap) и машиночитаемый JSON.

Ядро — CNN multi-label по патчам 384×384 + детерминированные CV-метрики + OCR-слой.
Внешняя сеть не нужна: без интернета система работает полностью.

Полное ТЗ, архитектура и план спринтов — в [PLAN.md](PLAN.md).

Магических чисел в коде нет: метки, пороги, гиперпараметры берутся из конфига.

### CV-baseline (С1)

Девять из десяти меток закрываются детерминированными метриками без обучения
(`unreadable` придёт из OCR в С3). Сырая метрика переводится в скор 0..1 линейной
интерполяцией между двумя якорями из `configs/base.yaml`:

| Метка | Метрика |
|---|---|
| `blur` | Tenengrad, нормированный на квадрат контраста |
| `glare` | доля площади в кластерах «ярко + плоско + ярче бумаги» |
| `shadow` | доля площади, где карта освещённости ниже медианы |
| `skew` | угол по профилю проекции, два прохода |
| `cropped` | доля периметра кадра, где штрихи рассечены границей |
| `low_resolution` | высота строки в рабочем разрешении |
| `low_contrast` | разрыв медиан бумаги и чернил |
| `noise` | σ шума по медиане высокочастотного отклика |
| `streaks` | аномальные колонки/строки фона |

Отчёт различает «дефекта нет» и «измерить нечем»: метки, неприменимые к этой
странице, попадают в `not_applicable`, а не выдаются нулём. Так бывает на
битональном скане (`low_contrast`, `noise`) и когда не удалось найти строки
текста (`low_resolution`).

### Якоря живут на корпус

Значения не универсальны: Tenengrad зависит от гарнитуры, кегля и dpi, а чернила
на границе кадра означают обрез для офисного скана и норму для архивного разворота.
Якоря с одного корпуса на другом дают вырожденный скор.

`configs/base.yaml` откалиброван по Tobacco3482. Для другого корпуса кладём оверлей
в `configs/corpora/`, он задаёт только отличия и наследует всё остальное:

```powershell
# посчитать якоря по своему корпусу
python -m src.metrics.calibrate_anchors --data data\raw\yenisei\images --limit 150

# запустить приложение с оверлеем
python -m src.app --corpus configs\corpora\yenisei.yaml
```

Инструмент ставит `good` на перцентиль типичной страницы, `bad` — в хвост. Это шкала
подозрительности для предразметки, а не пороги вердикта: настоящие пороги считаются
по PR-кривым в С6, когда появятся метки.

## Данные

| Корпус | Роль | Объём | Лицензия |
|---|---|---|---|
| [Tobacco3482](https://huggingface.co/datasets/prabhats0605/scanned-images-dataset-for-ocr-and-vlm-finetuning) | основной: разметка, обучение | 3482 скана, англ. | MIT |
| [YeniseiGovReports-TD](https://huggingface.co/datasets/anna4uonline/YeniseiGovReports-TD) | проверка обобщения на другой язык и домен | 1799 сканов, рус. | MIT |

Система рассчитана на оцифровку, где **кадр = страница** (планшет, МФУ, микрофильм).
Фотографии документа на столе она не оценивает: там вокруг листа есть фон, который
ломает и бинаризацию, и оценку полей. Для этого нужен отдельный этап детекции
страницы, и в объём проекта он не входит.

`data/`, `models/`, `runs/`, `reports/` — в `.gitignore`.
