# Оценка качества сканов документов

Принимает скан (jpg/png/pdf) и выдаёт вердикт `good` / `acceptable` / `bad`, список
дефектов с вероятностями, карту дефекта и машиночитаемый JSON.
Внешняя сеть не нужна: без интернета система работает полностью.

**Каждая метка берётся у того источника, который меряет её лучше.** Это результат
замера на реальных страницах, а не замысел: на отложенной выборке CV-метрики
обошли обученную сеть почти по всем меткам, но ошибаются они на непересекающихся
метках, и вместе дают больше, чем каждая по отдельности.

| Источник | Метки | Почему он |
|---|---|---|
| CV-метрики | `blur`, `glare`, `shadow`, `skew`, `cropped`, `low_resolution`, `streaks` | Детерминированы, объяснимы, обучения не требуют |
| CNN (ONNX) | `low_contrast`, `noise` | Единственные две, где CV-слой не выдаёт значения вовсе: корпус битональный, а на нём контраст и шум неизмеримы |
| OCR | `unreadable` | Метка выводится из распознавания по построению |

Распределение задаётся в конфиге (`sources`) и проверяется валидатором: метка
должна встречаться ровно один раз. Два источника на метку означали бы
необъявленный арбитраж, пропуск — метку, которую никто не считает.

Полное ТЗ, архитектура и журнал решений — в [PLAN.md](PLAN.md).

### Чем С5 закончился и почему это не провал

Сеть обучили в Colab (22 эпохи, сошлась на 12-й) и померили на реальных
страницах. DoD требовал, чтобы macro-F1 сети устойчиво превосходил CV-baseline,
а вышло наоборот. Причина названа прямо: в обучении было 8000 синтетических
страниц против 60 реальных, train-потеря упала до 0.0068 при val-потере 12.9 —
сеть выучила генератор деградаций, а не дефекты сканов. Дообучение на реальных
страницах дало прирост, но разрыв не закрыло.

Из этого замера и вырос гибрид: сеть осталась в системе ровно там, где
CV-слой бессилен. Подробности — `reports/cnn_vs_baseline_val.md` и решения
№39–40 в журнале.

### Карта дефекта

Grad-CAM не используется, и это осознанно. Он объясняет решение **сети**, а сеть
отвечает за две метки из десяти, причём обе глобальные — «где именно» у контраста
и шума не спрашивают. Остальные семь дают CV-метрики, у которых уже есть точное
доказательство: маска кластеров пересвета, карта освещённости, аномальные колонки,
приграничные штрихи. Рисовать поверх них Grad-CAM значило бы объяснять не тот
источник, который принял решение. Второе основание: Grad-CAM требует torch,
а он живёт в extra `train` — приложение обязано работать на базовых зависимостях.

Маски берутся из самих метрик, а не пишутся заново: показывать вторую, отдельно
посчитанную тень значило бы объяснять не то, по чему выставлен скор. Глобальным
меткам (`blur`, `skew`, `low_resolution`) карта не даётся вовсе — подсветить
«здесь размыто» на равномерно размытом скане честно нельзя.

## Разметка (С2)

```powershell
# 1. черновые метки по CV и очередь на разметку
python -m src.labeling.prelabel --data data\raw\tobacco3482\data `
    --corpus-name tobacco3482 --out data\labeled\prelabels_tobacco.jsonl `
    --queue data\labeled\queue_tobacco.json

# 2. разметчик: 1-9 переключают дефект, пробел - страница чистая,
#    стрелки - навигация, запись после каждой страницы
python -m src.labeling.app --data data\raw\tobacco3482\data `
    --queue data\labeled\queue_tobacco.json --labels data\labeled\labels.jsonl

# 3. сплит по документам + отчёт по частотам меток
python -m src.data.split --labels data\labeled\labels.jsonl --out data\splits
```

Очередь набирается наполовину случайно, наполовину — верхушкой по каждой метке.
Чистый рандом даёт правдивые частоты, но два-три примера редкого дефекта на 800
страниц; отбор только по подозрительности учит модель ровно тем дефектам, которые
CV и так ловит. `labels.jsonl` только дозаписывается: повторная разметка страницы
добавляет строку, при чтении берётся последняя, история правок остаётся.

### CV-метрики

Семь меток из десяти закрываются детерминированными метриками без обучения.
Ещё две (`low_contrast`, `noise`) CV-слой тоже умеет считать, но на битональном
корпусе не выдаёт вовсе — там они неизмеримы, и по замеру эти две отданы сети.
Сырая метрика переводится в скор 0..1 линейной интерполяцией между двумя якорями
из `configs/base.yaml`:

| Метка | Метрика |
|---|---|
| `blur` | Tenengrad, нормированный на квадрат контраста |
| `glare` | доля площади в кластерах «ярко + плоско + ярче бумаги» |
| `shadow` | доля площади, где карта освещённости ниже медианы |
| `skew` | угол по профилю проекции, два прохода |
| `cropped` | доля периметра кадра, где штрихи рассечены границей |
| `low_resolution` | высота строки в рабочем разрешении |
| `low_contrast` | разрыв медиан бумаги и чернил |
| `noise` | σ шума по медиане высокочастотного отклика |
| `streaks` | аномальные колонки/строки фона |

Отчёт различает «дефекта нет» и «измерить нечем»: метки, неприменимые к этой
странице, попадают в `not_applicable`, а не выдаются нулём. Так бывает на
битональном скане (`low_contrast`, `noise`) и когда не удалось найти строки
текста (`low_resolution`).

### Якоря живут на корпус

Значения не универсальны: Tenengrad зависит от гарнитуры, кегля и dpi, а чернила
на границе кадра означают обрез для офисного скана и норму для архивного разворота.
Якоря с одного корпуса на другом дают вырожденный скор.

`configs/base.yaml` откалиброван по Tobacco3482. Для другого корпуса кладём оверлей
в `configs/corpora/`, он задаёт только отличия и наследует всё остальное:

```powershell
# посчитать якоря по своему корпусу
python -m src.metrics.calibrate_anchors --data data\raw\yenisei\images --limit 150

# запустить приложение с оверлеем
python -m src.app --corpus configs\corpora\yenisei.yaml
```

Инструмент ставит `good` на перцентиль типичной страницы, `bad` — в хвост. Это шкала
подозрительности для предразметки, а не пороги вердикта.

## Пороги вердикта (С6)

Калибруется не порог, а **шкала**. Скоры трёх источников несовместимы: CV-метрика
нормирована по перцентилям корпуса, сеть выдаёт вероятность после сигмоиды,
OCR — свою величину. Один общий порог 0.5 на всех давал у `blur` точность 1.000
при полноте 0.080: ранжирование верное, но средние по патчам до 0.5 не доходят.

Поэтому каждой метке подбираются два якоря, и её скор приводится к общим 0..1 так,
что опорные точки шкалы попадают ровно в рабочие точки метки по PR-кривой.
Правило вердикта из плана при этом не меняется — меняется то, что в него подаётся.

```powershell
python -m src.models.calibrate --data data\raw\tobacco3482\data `
    --labels data\labeled\labels.jsonl --splits data\splits --part val --with-ocr
```

Вторым разделом команда печатает таблицу компромисса по порогам уже на уровне
страницы. Она нужна отдельно: правило требует, чтобы **ни одна** из девяти меток
не превысила порог, и целевой полноты на метку хватает, чтобы чистая страница
споткнулась хоть обо что-то. Поэтому страничный порог выходит строже опорных
точек шкалы, а `good` остаётся сравнительно редким вердиктом.

Читать вердикт следует так: `bad` — отклонить, `acceptable` — посмотреть глазами,
`good` — уверенное «точно чисто».

### Экспорт в ONNX

```powershell
python -m src.models.export_onnx --checkpoint models\finetune\best.ckpt `
    --out models\quality.onnx --sample data\raw\tobacco3482\data\<любая>.jpg
```

Сверка идёт по **вероятностям, а не по логитам**, и на входе, похожем на страницу.
Логит — величина без своего масштаба: на белом шуме сеть выдаёт −211…76, и
расхождение 0.13 там означает 0.4% относительных и 1e-4 после сигмоиды. Первая
версия проверки на этом забраковала исправный экспорт. Допуск 1e-3; фактически
получается 1.4e-05 на патчах настоящего скана.

страницы, и в объём проекта он не входит.
