### 1. Сигналы от DeepSeek-OCR

Модель: `deepseek-ai/DeepSeek-OCR`, HuggingFace, `trust_remote_code=True`.
**Сверься с карточкой модели и README репозитория перед написанием кода** — имена методов,
режимы разрешения, параметры `base_size` / `image_size` / `crop_mode`. Не угадывай сигнатуры.

Нам нужен не текст, а его «здоровье». Считай на каждый скан:

- доля символов вне ожидаемого алфавита (кириллица + латиница + цифры + пунктуация);
- доля слов вне словаря;
- **детект зацикливания** — VLM-OCR на плохом входе уходит в повтор фразы.
  Доля повторяющихся 5-грамм + максимальная длина повторяющегося блока;
- средний logprob на токен, если движок его отдаёт (vLLM отдаёт);
- **self-consistency**: прогнать один скан в двух режимах разрешения (низкий и высокий)
  и посчитать нормализованное расстояние Левенштейна между выходами.
  Расхождение = скан ненадёжен. Ground truth не нужен — это главный сигнал этапа.

Всё это ложится в те же записи результатов, что уже использует проект.

### 2. VLM-судья

Модель уточню отдельно. Сделай слой абстракции, чтобы бэкенд менялся одной строкой конфига.
Температура 0.

Промпт ниже — шаблон. **Подставь в него мой фактический список дефектов из кода проекта**,
сохранив структуру, шкалу и механические правила вердикта. Дальше промпт не трогай:
любые правки только по моему явному запросу, иначе метрики разных прогонов несравнимы.

```
You are a document scan quality inspector. You judge IMAGE QUALITY only.
Never comment on the document's meaning, topic, or content correctness.

Rate the scan on each axis. Use the scale strictly:
0 = not present / perfect, 1 = slight, 2 = moderate, 3 = severe, 4 = makes text unreadable

Axes:
<СЮДА — список осей из проекта, по строке на ось: имя + короткое определение>

Also report:
- rotation_deg: one of 0, 90, 180, 270 (dominant text orientation)
- blank_page: true if there is no meaningful text
- legible_fraction: estimated share of the page's text a human could read, 0.0-1.0

Verdict rules (apply mechanically, do not override with intuition):
<СЮДА — пороговые правила из конфига проекта>

Judge only what is visible. Do not guess about parts you cannot see.
Output ONLY valid JSON, no markdown fences, no explanation:

<СЮДА — пример валидного JSON с теми же ключами>
```

Требования к обвязке:
- ответ валидируй по схеме (pydantic); невалидный — один ретрай, потом `status: "failed"`;
- **никогда не подставляй дефолтные оценки вместо неудавшегося вызова**.
  Это самая частая тихая ошибка: модель не ответила, код записал нули, весь брак уехал в «good»;
- заложи место под few-shot примеры (3–5 изображений: плохой / пограничный / хороший).
  Я добавлю их сам — они дают больше, чем правки текста промпта.

### 3. Каскад

Свяжи этапы так, чтобы дорогие модели не гонялись по всему датасету:
дешёвые метрики → OCR-сигналы → VLM только на серой зоне.
Если в проекте уже есть логика вердикта, встрой каскад в неё, а не рядом.
Логируй, сколько сканов отсеял каждый этап.

### 4. Валидация

Если этого ещё нет:
- скрипт-разметчик: показывает скан, я жму клавишу, результат в `golden.jsonl`, с докаткой и возвратом назад;
- выборка для золотого набора — **стратифицированная по метрикам первого этапа**, не 200 подряд;
- метрики: confusion matrix, precision/recall/F1 по классам, Cohen's kappa между моделью и мной,
  ROC-AUC для бинарного среза.

Мне это нужно на защиту — без цифр пайплайн не считается сделанным.

## Правила работы с кодом

- Стиль, структура и соглашения — как в существующем коде, не как тебе привычнее.
- Новые зависимости — только с объяснением, зачем.
- Кеш результатов по хешу файла, повторный прогон не пересчитывает готовое.
- Ошибка на одном файле не роняет прогон: пиши `status` и `error`, продолжай.
- Изменения по одному логическому куску за раз, каждый проверяем отдельно.
- Тесты на новые метрики: синтетически испорченная картинка → метрика реагирует ожидаемо.
