## 1. Цель

Приложение на Python, которое принимает скан документа и автоматически выдаёт:

1. **Вердикт**: `good` / `acceptable` / `bad`
2. **Список дефектов** с вероятностями (multi-label)
3. **Локализацию** дефекта на изображении (heatmap)
4. **Машиночитаемый JSON** — чтобы систему можно было встроить в автоматическую проверку потока сканов

Интерфейс: Gradio (одиночный режим + батч) и CLI-режим для обработки папки.

## 3. Архитектура

```
скан (jpg/png/pdf)
   │
   ├─► препроцессинг: загрузка, деskew-детект, нарезка на патчи 384×384 (сетка ~6×9 для A4@300dpi)
   │
   ├─► [A] CV-метрики (детерминированные, без обучения)
   │        Laplacian var, Tenengrad, доля и кластеры пересвета,
   │        угол перекоса (Radon/Hough), RMS-контраст, оценка высоты строки, уровень шума
   │
   ├─► [B] CNN multi-label (timm, 10 сигмоид)
   │        инференс по патчам → агрегация: max для локальных, mean для глобальных дефектов
   │
   ├─► [C] OCR-слой (EasyOCR/Tesseract rus)
   │        средняя confidence, доля «мусорных» символов, плотность распознанного текста
   │
   └─► агрегатор → QualityReport (pydantic)
            вердикт по правилу с калиброванными порогами
            + Grad-CAM heatmap
            + (опц.) текстовое объяснение через внешний API
```

**[A] — baseline.** Обязателен: в записке нужно сравнение «CV-метрики vs CNN vs CNN+OCR».
**[B] — ядро.** Multi-label, `BCEWithLogitsLoss` + `pos_weight` под дисбаланс.
**[C] — источник метки `unreadable`** и практическое обоснование пользы системы.

### Почему патчи, а не ресайз всей страницы

A4 в 300 dpi — это 2480×3508. При ресайзе в 224×224 текст превращается в серый шум, и `blur` / `low_resolution` становятся физически недетектируемыми. Поэтому:

- **train:** случайные патчи 384×384 из исходного разрешения, метки наследуются от изображения (для глобальных дефектов) или от маски деградации (для локальных)
- **inference:** регулярная сетка патчей + агрегация

## 4. Таксономия дефектов

Multi-label (дефекты сочетаются), 10 меток:

| Метка | Определение | CV-сигнал | Как синтезировать |
|---|---|---|---|
| `blur` | Расфокус или смаз, края символов размыты | низкая дисперсия Лапласиана, Tenengrad | GaussianBlur, MotionBlur (Albumentations) |
| `glare` | Локальный пересвет, участок выбит в белое | кластеры пикселей >245 с площадью > порога | радиальный/эллиптический градиент яркости |
| `shadow` | Затемнение от сгиба, переплёта, края крышки | градиент яркости по краю, локально низкая медиана | Augraphy `ShadowCast`, `LightingGradient` |
| `skew` | Перекос строк > 2° | пик Radon-преобразования вне 0° | affine rotation |
| `cropped` | Обрезан край документа, часть текста вне кадра | отсутствие полей, текст вплотную к границе | случайный crop края |
| `low_resolution` | Высота строки < ~15 px, символы неразличимы | оценка высоты строки, спектр высоких частот | downscale → upscale |
| `low_contrast` | Блёклая печать, серый текст на сером фоне | RMS-контраст, узкая гистограмма | сжатие диапазона яркости, gamma |
| `noise` | Шум, зерно, грязь на стекле сканера | оценка σ шума, высокочастотная энергия | GaussNoise, ISONoise, соль-перец |
| `streaks` | Полосы, следы валиков, артефакты копира | периодичность по столбцам/строкам | Augraphy `DirtyRollers`, `BadPhotoCopy` |
| `unreadable` | Текст не распознаётся | OCR confidence + доля мусорных символов | производная метка, ставится автоматом по [C] |

`unreadable` — **не отдельный дефект, а следствие**. Размечается автоматически, в обучении участвует как отдельный выход, но в правиле вердикта имеет наибольший вес.

### Правило вердикта

Пороги калибруются по PR-кривым (спринт 6), не подбираются на глаз. Целевая асимметрия: **пропустить плохой скан хуже, чем отклонить хороший**, поэтому по `unreadable` и `blur` целимся в recall ≥ 0.95.

```
bad         := unreadable > τ_u  ИЛИ  любой дефект > τ_high
acceptable  := есть дефекты в диапазоне (τ_low, τ_high]
good        := все метки ≤ τ_low
```

## 6. Конфиг (`configs/base.yaml`)

Никаких магических чисел в коде — всё сюда.

```yaml
labels: [blur, glare, shadow, skew, cropped, low_resolution,
         low_contrast, noise, streaks, unreadable]

data:
  patch_size: 384
  target_dpi: 300
  grid: {rows: 9, cols: 6}
  aggregation:            # как схлопывать предсказания по патчам
    local:  [glare, shadow, cropped, streaks]      # max
    global: [blur, low_resolution, low_contrast, noise, skew, unreadable]  # mean

model:
  backbone: efficientnet_b0
  pretrained: true
  dropout: 0.2

train:
  epochs: 30
  batch_size: 32
  lr: 3.0e-4
  optimizer: adamw
  scheduler: cosine
  seed: 42
  pos_weight: auto        # считать по частотам в train

verdict:
  tau_low: 0.30           # калибруется в calibrate.py, здесь — начальные значения
  tau_high: 0.60
  tau_unreadable: 0.50
```

## 7. Стратегия данных

### 7.1 Порядок операций (нарушать нельзя)

1. Ручная разметка реальных → `labels.jsonl`
2. **Сплит по документам** → `splits/{train,val,test}.json`
3. Синтетика — генерируется **отдельно для каждой части**, из эталонов только этой части
4. Обучение
5. Тест — один раз, в самом конце, только на реальных из `test.json`

Причина сплита по документам: у договора страницы почти идентичны (та же бумага, тот же прогон сканера). Случайное перемешивание страниц = утечка, метрики завышаются на 10–15%.

### 7.2 Бюджет

| Что | Объём |
|---|---|
| Ручная разметка реальных | 600–800 (~4 часа) |
| Из них ожидаемо чистых | 40–60% → эталоны для деградаций |
| Синтетика (6–8 деградаций на эталон) | 8–15 тыс. |
| Test (реальные, руками, не трогать до конца) | 150–200 |

### 7.3 Разметчик

Минимальный Gradio-интерфейс: изображение + zoom + 10 чекбоксов + кнопки «дальше/назад» + горячие клавиши + автосохранение в JSONL после каждого изображения. Предзаполнение чекбоксов черновыми метками из `prelabel.py` — ускоряет работу вдвое.

### 7.4 Синтетика

Не генерируем документы с нуля — деградируем **чистые реальные сканы**. Домен сохраняется (те же бланки, шрифты, печати, фон бумаги), метки известны по построению. Для локальных дефектов (`glare`, `shadow`, `streaks`, `cropped`) сохраняем **маску области** — она нужна для корректной разметки патчей.

Контроль частот: следим, чтобы редкие метки встречались не реже ~15% выборки, иначе `pos_weight` не спасёт.

## 10. Метрики для защиты

1. **Per-label**: precision, recall, F1, AP по каждому из 10 дефектов + macro-F1
2. **Вердикт**: accuracy, F1, confusion matrix на реальном тесте
3. **Практическая польза**: корреляция Спирмена между предсказанным скором качества и фактической ошибкой OCR — доказывает, что «плохой скан» по мнению системы действительно плохо распознаётся
4. **Ablation**: CV-baseline → CNN → CNN+OCR, вклад каждого компонента
5. **Производительность**: время инференса на CPU и GPU, размер модели
6. **Кросс-валидация**: 5 фолдов, среднее ± std

## 12. Риски

| Риск | Проявление | Что делаем |
|---|---|---|
| Утечка через страницы одного документа | Метрики завышены на 10–15% | Сплит по документам, синтетика после сплита |
| Синтетика ≠ реальность | Модель выучит артефакты генератора | Тест только на реальных, разнообразие деградаций, домен от реальных эталонов |
| Ресайз убивает мелкие дефекты | `blur`, `low_resolution` не детектируются | Патчи из полного разрешения |
| Дисбаланс редких меток | `streaks`, `cropped` не выучиваются | Контроль частот при генерации, `pos_weight`, отдельный анализ per-label recall |
| Обрыв сессии Colab | Потеря обучения | Чекпоинт каждую эпоху на Drive, `--resume auto` |
| Маленький тест | Широкий доверительный интервал | 5-fold кросс-валидация, приводить разброс |
| Разметка съедает время | Срыв сроков | Предразметка автоматом, разметчик с горячими клавишами, лимит 800 изображений |

## 13. Журнал решений

| № | Решение | Обоснование |
|---|---|---|
| 1 | Ядро — CNN multi-label, не LLM/VLM | Дефекты сканов — статистика пикселей, не семантика. CNN точнее, быстрее, обучается на T4 |
| 2 | Внешний API — только для текстового отчёта, опционально | Автоматическая проверка не должна зависеть от сети |
| 3 | Синтетика поверх реальных чистых, не генерация с нуля | Совпадение домена: те же бланки, шрифты, бумага |
| 4 | Обучение и инференс на патчах 384×384 | При ресайзе A4 в 224px текст исчезает |
| 5 | Сплит по документам | Страницы одного договора почти идентичны |
| 6 | `moire` заменён на `streaks` | Домен — сканы А4 с МФУ, не фото экрана |
| 7 | `unreadable` размечается автоматом по OCR | Объективный ground truth вместо субъективной оценки |
| 8 | Асимметричные пороги, recall > precision | Пропустить плохой скан дороже, чем отклонить хороший |
| 9 | Целевой Python 3.9, а не 3.10+ | Локально стоит 3.9.13; ставить второй интерпретатор ради `X \| Y` не окупается |
| 10 | Конфиг с `extra="forbid"`, валидация покрытия меток в `aggregation` | Опечатка в yaml должна падать при старте, а не тихо менять поведение обучения |
| 11 | Пины `pydantic<2.10` и `huggingface-hub<1.0` | Gradio 5 требует Python 3.10+, значит сидим на 4.44.1; она несовместима с pydantic 2.10+ (падает генерация API-схемы) и с hub 1.0 (удалён `HfFolder`). Снимать пины — только вместе с переездом на Python 3.10+ |
| 12 | `GRADIO_ANALYTICS_ENABLED=False` при старте приложения | Gradio при импорте ходит в api.gradio.app, а система обязана работать без сети |
| 13 | Бинаризация чернил — локальный порог, а не Оцу; отступ растёт вместе с σ шума | Тень сдвигает глобальный порог, и затемнённая половина страницы уходит в «текст»: поля схлопываются, чистый скан помечается как `cropped`. Фиксированный отступ на зернистом скане склеивает все строки в одну — высота строки становится равной высоте страницы |
| 14 | `blur` считается по `tenengrad_norm` = Tenengrad / (разрыв бумага-чернила)² | Градиент пропорционален перепаду яркости: без нормировки блёклая печать даёт тот же провал резкости, что и расфокус, и `low_contrast` неотличим от `blur` |
| 15 | `low_resolution` меряется в пикселях ИСХОДНОГО файла | Загрузчик приводит страницу к 300 dpi; после апскейла скана 150 dpi высота строки возвращается к норме и дефект исчезает из метрики |
| 16 | Блик = «ярче порога» И «ярче собственной бумаги» И «без фактуры» | Одного порога 245 мало: белая бумага сама ярче, и любой чистый скан получал `glare` = 1.0. Блик — это потеря информации, поэтому проверяется ещё и локальная дисперсия |
| 17 | Резкость и шум — по патчам с текстом, геометрия и освещённость — по всей странице | На пустом поле бумаги краёв нет, и метрика резкости на нём всегда скажет «размыто» |
